# CLAUDE.md – Inn Menu Simulator

## What this is
Browser-based, system-agnostic fantasy RPG inn menu generator. Static `index.html` + vanilla JS, no build step, no framework. Data-first: the generator is a thin layer over JSON files in `data/`.

## Where Things Live
One owner per fact — link, don't restate.

| Information | Look here |
|---|---|
| Pitch, quick start, project layout | `README.md` |
| Architecture, tag taxonomy, tuning knobs, editing-data reference | `docs/DESIGN.md` |
| GitHub account/repo/Pages setup, troubleshooting | `docs/SETUP.md` |
| The actual content (dishes, ingredients, prices, biomes, events) | `data/*.json` |
| Generation logic, `TUNING` block | `src/generator.js` |
| Form wiring, rendering, flavor-pack merging | `src/ui.js` |
| Optional LLM flavor polish | `src/llm.js` |

### Hierarchy of truth
1. **Data wins.** `data/*.json` is the actual product — which dish shows up where is decided there, not in docs.
2. **`docs/DESIGN.md` explains.** Tag taxonomy, tuning knobs, and the *why* behind generation rules — read it before editing data or `src/generator.js`.
3. **Smoke reports are generated, not authored.** `out/smoke-report.md` / `out/smoke-deep.md` are overwritten on every run — never hand-edit them.

## Commands
```bash
python3 -m http.server          # serve locally; opening index.html via file:// breaks fetch()

npm run smoke                   # regression check: SAMPLES=N WORLDS=N RARE_FACTOR= OVER_FACTOR=
node scripts/smoke-deep.js      # editorial audit: per-axis breakdown + structural data scans
node scripts/balance-probe.js   # read-only: import/staple frequency probe at low tiers
node scripts/import-label-check.js  # read-only: before/after probe for import labels
node scripts/tag-origins.js     # MUTATES data/ingredients.json in place — one-shot, not a check
```

## Deployment
- Single branch (`main`); GitHub Pages deploys straight from root on every push. No build step, no CI workflow — a bad commit to `main` goes live immediately.
- **Commit/PR hygiene:** no AI-attribution footers — don't append session URLs, "Generated by" lines, or `Co-authored-by` trailers to commits or PR bodies (`.claude/settings.json` disables the automatic ones). GitHub's integration can still auto-append a footer to a PR body *on creation*; if that happens, immediately re-set the description to strip it (an update doesn't re-add it).

## Gotchas
- **Tags are case-sensitive lowercase hyphenated strings**, matched by exact string comparison. A typo silently makes a dish or ingredient unreachable instead of erroring — run `npm run smoke` after any data edit to catch it.
- **Cuisine tags aren't biomes.** `mediterranean` / `nordic` etc. describe cuisine, not a valid `biomes` value — `smoke-deep.js` check C1 flags this.
- **Retune `TUNING` (top of `src/generator.js`) deliberately.** It's one block of interacting knobs (authored/procedural mix, event boosts, variety steps, peculiar dampening, tier-fit) — change one, then run `npm run smoke` before and after to see the effect on distribution rather than eyeballing a few generated menus.
- **`scripts/tag-origins.js` writes to disk.** Unlike the other scripts under `scripts/`, it isn't read-only — it edits `data/ingredients.json` in place via regex. Diff before committing.
